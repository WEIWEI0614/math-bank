## 1. 这套系统解决什么问题

一位国际数学教师手上有 12,030 道历年真题，但缺三件事：

| 痛点 | 系统的答案 |
|---|---|
| 不知道**每个学生具体弱在哪** | 逐知识点 Elo 能力分 + 全班热力图 |
| 布置作业**只能全班同一张卷** | 按每人薄弱点单独生成专项练习 |
| 学生刷题**只对答案不复盘** | 错因必填 + 答后对照 Mark Scheme 订正 |
| 学生成绩数据**散在微信和纸面上** | 全部作答落本地 SQLite，随时导出 |

**它不是"刷题网站"，是一个学情记录系统。** 题目只是载体，产出是"谁弱在哪"的诊断。

### 两条贯穿始终的设计原则

1. **零 LLM 调用** —— 运行时不调任何 AI 接口，判分、评估、反馈全是确定性代码。可复现、可解释、零成本。
2. **数据不出本机** —— 本机模式只监听 `127.0.0.1`，作答写本地 SQLite，不上传云端。

> 这两条不是技术限制，是刻意选择。**学生姓名 + 成绩属于敏感数据**，留在老师自己的电脑上是特性而非缺陷。

## 2. 两种运行方式

### 方式一：本地服务（推荐，多人/长期使用）

```bash
python3 site/serve.py          # → http://127.0.0.1:8770
```

- 作答写入 `bank.sqlite`，**换设备、换浏览器、清缓存都不丢**
- 教师能看到全班数据
- 断网也能用（作答先进队列，恢复后自动补传）

### 方式二：直接打开（单机自用）

```bash
open site/index.html
```

- 无需 Python，双击即可
- 数据存在浏览器 `localStorage`，**换设备即丢失**
- 适合学生自己在家用、或老师做演示

> ⚠️ 方式二下教师端不可用（没有服务端就没有全班数据）。

## 3. 角色与权限

| 角色 | 登录需要 | 能看到 | 不能做 |
|---|---|---|---|
| **学生** | 姓名 + 班级码 | 自己的练习、薄弱点、数据 | 看别人的数据 |
| **教师** | 教师口令 | 全班花名册、热力图、作答流水 | 以学生身份作答 |

- 首次用姓名登录会**自动建号**，不需要预先导入花名册
- 会话是 Bearer token，**有效期 7 天**，存在浏览器里
- 权限由**服务端强制**：学生 token 即使手工改请求也拿不到全班数据

### 修改默认口令

默认口令是 `shuxue2026`（教师）/ `banji2026`（班级码），**生产环境务必改掉**。

```bash
# 方式 A：环境变量（优先级最高）
TEACHER_KEY="你的口令" STUDENT_CODE="你的班级码" python3 site/serve.py

# 方式 B：密钥文件（首次启动自动生成，权限 0600）
echo "你的口令"   > .teacher_key
echo "你的班级码" > .student_code
```

优先级：**环境变量 > 密钥文件 > 内置默认值**。两个密钥文件已被 git 忽略，不会误提交。

## 4. 教师使用流程

### 4.1 首次启动

```bash
cd math-bank
python3 site/serve.py
```

控制台会打印地址与默认口令：

```
练习站: http://127.0.0.1:8770/   （仅本机可访问，数据写入 /path/to/bank.sqlite）
教师口令: shuxue2026   学生班级码: banji2026
```

浏览器打开 `http://127.0.0.1:8770`，用教师口令登录。

### 4.2 让学生开始练习

1. 把**班级码**告诉学生，`Ctrl+C` 之外的任何时间都能登录
2. 学生打开同一地址 → 选"学生" → 输入**真实姓名**（这就是花名册里的名字）+ 班级码
3. 学生做题，数据自动上报

> 💡 姓名就是主键。**让学生用固定姓名登录**，否则会出现"张三"和"张三 "两个账号。

### 4.3 看花名册（学生一览）

| 列 | 含义 |
|---|---|
| 学生 | 登录时填的姓名 |
| 累计题数 | 该生总作答题数 |
| 正确率 | 历史平均得分（1 / 0.5 / 0） |
| 最近练习 | 今天 / 昨天 / N 天前 —— **用来抓"谁没练"** |
| 需补知识点 | 能力分最低的 3 个知识点 |

**怎么用**：先按"最近练习"看谁掉了队，再看"需补知识点"决定给谁补什么。

### 4.4 看掌握热力图

行 = 知识点，列 = 学生，格子 = 能力分（颜色越暖越弱）。

**怎么用**：
- **竖着看一列** = 某个学生的全貌
- **横着看一行** = 某个知识点的全班情况 —— **一行全暖，说明是教学问题，不是学生问题**

> 热力图最多显示 60 个知识点。库里有 52 个知识点都叫"综合题"，
> 界面会在重名知识点下补一行小字（章名 + 知识点编号尾段）帮助区分。

### 4.5 一键出专项练习卷

1. 在"学生一览"页，**从下拉框选学生**（不要手打名字，拼错会报 404）
2. 可选：指定单元（留空 = 不筛选，覆盖全部薄弱点）
3. 填题数（1–50，默认 10）
4. 点"生成"

系统会按该生**引擎判定的薄弱知识点**抽题，生成一个 HTML 文件：

- 卷头写明**实际覆盖了哪几个知识点、各几题**（不会静默降级成单单元随机卷）
- 客观题附**参考答案**
- 解答题没有简答时，附**判分细则**（Mark Scheme 原文，已裁掉版权声明与水印）
- 含原卷题图，KaTeX 渲染公式

打印或发给学生即可。

> ⚠️ 如果指定了单元，而该生的薄弱点不在这个单元里，卷子会变短 ——
> 界面会明确提示"薄弱知识点命中 N 个"，不会让你误以为覆盖完整。

### 4.6 看最近作答

全班作答流水，最近 80 条倒序：时间 / 学生 / 题目 ID / 得分 / 用时 / 错因。

**怎么用**：筛"错因"列 —— 如果连续多条都是"计算抄写失误"，说明这批学生的问题不在概念，限时计算训练更有效。

### 4.7 导出数据

点"导出全部数据"下载 `全部学生数据.json`，含每个学生的：

- 逐条作答日志（题目 ID、时间、得分、用时、错因）
- 各知识点能力分与作答次数

用途：期末归档、自己做进一步分析、备份。

## 5. 学生使用流程

### 5.1 登录

打开地址 → 选"学生" → 填姓名 + 班级码 → 进入。

### 5.2 做一轮练习

一轮 **10 题**，选题配比：

| 类型 | 占比 | 你会感觉到 |
|---|---:|---|
| 补短板 | 60% | 反复出现你最弱的题型 |
| 间隔重复 | 25% | 之前练过但没练熟的 |
| 拔高 | 15% | 你已经掌握得比较好的，加难度 |

每题会标出**为什么选它**（补短板 / 间隔重复 / 拔高 / 补齐）。

**答题步骤**：

1. 看题 —— 题干以**原卷截图为主**，文字版折叠在下面（OCR 有残损时以图为准）
2. 客观题：直接点选项，**即时判分**（正确选项会标绿）
3. 主观题：想好后点"自评"
4. 自评时选**你实际做到哪一步**，并**必选一个错因**
5. 提交后对照**参考答案 / 判分细则**订正
6. 可"跳过本题"或"结束本轮"

**刷新页面不会丢进度** —— 未完成的一轮会保存 2 小时。

### 5.3 看薄弱点

按能力分从低到高排序的条形图（最多 18 个知识点），并给出**处方建议**：

| 你看到的提示 | 含义 |
|---|---|
| 能力分 + 彩色条 | 样本充足（≥15 次），可信 |
| "样本偏少 N 次" | 3–14 次，趋势可参考，绝对值别当真 |
| "样本不足 N 次" | <3 次，不显示分数，只显示"—" |
| "错因集中在运算" | 处方是**限时计算训练**，不是重学概念 |
| "错因集中在概念" | 处方是**回讲义重学**，不是刷题 |
| "错因集中在建模列式" | 处方是**专练把文字转成方程** |

### 5.4 我的数据

- 累计作答题数 / 已练知识点数 / 待同步条数
- **导出 JSON** —— 换设备时把练习记录带走
- **导入 JSON** —— 合并到当前身份（自动去重，不会覆盖历史）
- **清空本机副本** —— 只清浏览器缓存，**服务器上的作答保留**，下次同步会拉回来

## 6. 界面导览

### 学生端（3 页）

| 页 | 内容 |
|---|---|
| **练习** | 选题 → 作答 → 自评 → 订正 → 本轮小结 |
| **薄弱点** | 能力分条形图 + 错因分布 + 处方建议 |
| **我的数据** | 累计统计、导入导出、清空本机副本 |

### 教师端（3 页）

| 页 | 内容 |
|---|---|
| **学生一览** | 花名册（题数 / 正确率 / 最近活跃 / 最弱 3 项）+ 出卷入口 |
| **掌握热力** | 知识点 × 学生 能力分矩阵 |
| **最近作答** | 全班作答流水（最近 80 条）+ 导出 |

顶部可**切换身份**（教师 ⇄ 学生），右上角**退出**。

## 7. 能力分怎么读

| 能力分 | 大致含义 |
|---|---|
| < 950 | 明显薄弱，优先补 |
| 950 – 1100 | 中等，需要练熟 |
| > 1100 | 掌握较好，可拔高 |
| > 1150 | 会被选入"拔高"题池 |

初始分 **1000**。分数是**相对值**，用于**排序**找出最弱项 —— 不要把它当成"正确率"。

**两个前提要记住**：

1. 能力分只在**同一学生、不同知识点之间**可比，跨学生比较意义有限
2. 样本 < 15 次时系统会隐藏分数，这是防你被噪声误导

算法细节见 [ADAPTIVE-ENGINE.md](ADAPTIVE-ENGINE.md)。

## 8. 七类错因怎么用

| 错因 | 含义 | 对应的处方 |
|---|---|---|
| `concept` 概念不清 | 不知道该用什么知识 | 回讲义重学 |
| `procedure` 步骤方法错 | 知道用什么，但流程走错 | 练标准步骤 |
| `setup` 建模列式错 | 读不懂题 / 列不出式子 | 专练"文字 → 方程" |
| `algebra` 代数运算失误 | 式子对，化简算错 | 限时代数训练 |
| `calc` 计算抄写失误 | 方法对，数字算错或抄错 | 限时计算训练 + 检查习惯 |
| `time` 没做完 | 会做但来不及 | 限时模考 |
| `misread` 看错题目 | 题目看错了 | 读题圈画训练 |

> 💡 **错因是本系统最有价值的字段。** 系统会自动统计每个人的错因分布并给处方。
> 教师端"最近作答"里按错因筛选，能直接看出全班是概念问题还是运算问题。

## 9. 典型教学场景

### 场景 A：课后作业（每周）

1. 教师在"学生一览"看谁最近没练 → 提醒
2. 学生自己练 1–2 轮（20 分钟）
3. 教师看热力图，找出**全班共同的暖色行** → 下节课重点讲

### 场景 B：一对一补弱（考前）

1. 打开"学生一览"，选该生
2. 看"需补知识点"最弱 3 项
3. 点"生成"出一份专项卷（10 题）
4. 打印，下次课面批

### 场景 C：错因归因（月度）

1. "最近作答"按错因筛
2. 若 `calc` / `algebra` 占比高 → 加限时计算训练，别再讲概念
3. 若 `concept` 占比高 → 回讲义，刷题无效

### 场景 D：学期归档

1. 教师"导出全部数据" → `全部学生数据.json`
2. 存到你的教学档案
3. `bank.sqlite` 一并备份（它就是全部原始数据）

## 10. 常见问题

**Q：学生换电脑了，记录还在吗？**
A：用方式一（本地服务）就在 —— 数据在服务器的 `bank.sqlite` 里。学生用同样姓名登录即可。
用方式二（直接打开）则不在，需要先在旧设备"我的数据"导出 JSON，再到新设备导入。

**Q：能不能让多个学生同时用？**
A：能。同一台机器起服务，学生各自用姓名登录，数据互不影响（服务端按姓名隔离）。
但**本机模式只监听 127.0.0.1**，局域网其他设备访问不到 —— 这是安全设计，见 [SECURITY.md](SECURITY.md)。

**Q：为什么有些题不显示图片？**
A：原卷图片因版权与体积未随仓库分发。没有图片时系统会自动以文字题干呈现。
如果你有授权，把图片放到 `site/data/img/` 即可自动生效。

**Q：为什么有些题的答案是空的 / 明显被截断？**
A：这是已知数据缺陷，3,093 题（25.7%）的答案恰好卡在 1200 字符被截断。
详见 [KNOWN-ISSUES.md](KNOWN-ISSUES.md)。**不要拿答案文本做自动讲解。**

**Q：能力分为什么有时候显示"—"？**
A：该知识点作答不足 15 次，系统主动隐藏分数避免误导。继续练就会显示。

**Q：数据会上传到网上吗？**
A：不会。本机模式只监听 `127.0.0.1`，零外部请求。运行时不调用任何 AI 接口。

**Q：`bank.sqlite` 能直接打开看吗？**
A：能，用任何 SQLite 工具。表结构见 [ARCHITECTURE.md](ARCHITECTURE.md#5-数据库)。

**Q：怎么彻底重来？**
A：删掉 `bank.sqlite` 即可（会丢失全部作答记录，**先导出备份**）。
学生浏览器里的本机副本，在"我的数据"页点"清空本机副本"。

**Q：教师口令忘了怎么办？**
A：删掉仓库根目录的 `.teacher_key` 文件，重启服务会重新生成默认口令。
如果用的是环境变量，改环境变量即可。
