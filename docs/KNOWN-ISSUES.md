## 1. 知识点悬空引用：11.1% 题目无法被选中 🔴

**规模：1,331 题（11.1%）的 `topic_id` 在其所属单元的 `topics[]` 里不存在。**

### 为什么会这样

`topics[]` 是**按单元打包**的。许多题目引用的知识点 ID（如 `TP-0107`）在**别的单元**里是合法的
（实测 `TP-0107` = "积分技巧"，属于 CIE9709P3），但没有出现在引用它的那个单元的 `topics[]` 里。

少数 ID（如 `TP-0007`）**在整个库里都不存在**。

### 为什么这会让题目消失

出题逻辑 `pick()` 只遍历**本单元的 `DATA.topics`**：

```js
const tp = DATA.topics.filter(t => (t.nq>0 || topicCount[t.id]>0) && ...);
const takeQ = (t) => {
  const candidates = DATA.questions.filter(x => x[1] === t.id && !chosen.has(x[0]));
  ...
};
```

题目只能通过 `x[1] === t.id` 命中，而 `t` 来自 `tp`。
**`topic_id` 不在 `topics[]` 里的题目，永远不会被自适应出题选中。**

### 附带影响

- 知识点**名称显示为原始 ID**（如 `TP-0107`）而不是中文名
- **章节未知** —— 章节筛选与章计数都受影响
- `ability()` 找不到兄弟节点 → 这类知识点**不做章节收缩**，样本少时能力分会更极端

> 唯一例外：断点续做恢复的轮次（`loadRound` 按 qid 恢复）仍可能包含这些题目。

### 修复方向

数据里已有 `RAWGAP-<UNIT>` 占位知识点（当前 708 题在用），说明原设计就打算用它兜底。
两条路：

1. **补 `topics[]`** —— 把被引用的知识点条目补进对应单元（推荐，保留知识点语义）
2. **重映射到 `RAWGAP-<UNIT>`** —— 快速兜底，但会丢失知识点粒度

## 2. 答案文本定长截断 🔴

**规模：3,093 题（25.7%）的答案长度恰好等于 1200 字符。**

### 根因

不是偶发抽错，是**从合并文档里切 1200 字符固定窗口**造成的。

**证据**：3,093 题的答案长度**精确等于 1200** 这个整数 —— 随机错误不可能产生这种分布。

### 影响

🔴 **任何基于答案文本的自动讲解 / 自动判分都会输出错误内容**。
被截断的答案会在句子中间断掉，看起来"像是对的"，实则残缺。

### 分层情况

问题集中在 Edexcel 与竞赛题；CIE 此前已部分修过。

### 规避方式

- ✅ **做诊断、排薄弱点** —— 不受影响（只用得分与用时，不用答案文本）
- ✅ **出专项练习卷** —— 客观题附参考答案可用；解答题附的是判分细则
- ❌ **拿答案文本做自动讲解** —— 会输出残缺内容
- ❌ **拿答案文本做自动判分** —— 不可靠

### 修复方向

改为从 `__ms.png` 原卷图重新抽取（OCR + 人工抽检），而不是继续切定长窗口。

## 4. 题目图与答案图错配 🔴

已确认多例：同一 `qid` 下的题干图、答案图、答案文本**三者可能互不一致**。

**规避**：出卷时前端只取题干图（过滤掉文件名含 `ms` / `answer` 的），
但**无法自动检测图与题是否配对** —— 需要人工抽查。

> 桌面旧清单 `_fig_mismatch.json` 只覆盖 `__full.png` 且只涉及 CIE，
> **`__ms` 条目为 0** —— 答案侧是审计盲区。

## 5. 题干 OCR 残损 🟡

**普遍存在**：上标丢失（`x2` 而非 `x²`）、多行顺序错乱、公式被拆散。

**规避**：前端把**原卷截图作为主显**，文字版折叠在下方 —— 正是为了应对这个问题。
**以图为准，文字版只作参考。**

## 8. 重名知识点 🟡

库里有 **52 个知识点都叫"综合题"** —— 只看名字完全无法区分。

**规避**：热力图会在重名知识点下补一行小字（章名 + 知识点编号尾段）。

## 9. 手写过程分无法判定 🟡

系统只判：

- 客观题（选择题）：`objectiveAnswer()` 自动判
- 主观题：学生**自评**（选"实际做到哪一步" + 错因）

**Mark Scheme 里的 M 分（方法分）无法自动判定** —— 需要人工阅卷。

**影响**：能力分对主观题有系统性偏差（学生倾向于高估自己）。

---

## 10. 图片资源未随仓库分发 🟡

31,532 张 PNG（2.9 GB）因**版权**（CAIE / Pearson Edexcel / UKMT）与**体积**不随仓库分发。

**影响**：无图环境下题目不显示原卷截图，改以文字题干呈现 —— 而文字题干有 OCR 残损（见 §5）。

**规避**：如果你有授权，把图片放到 `site/data/img/` 即可自动生效，无需改代码。

## 复现方法

仓库自带自检脚本，一条命令覆盖上述大部分检查：

```bash
python3 scripts/check_data.py
```

它会报出：字段数异常、`topic_id` 悬空、章节 `parent` 悬空、答案长度尖峰、`qid` 重复、
与 `index.js` 登记题量不符。

### 手动复现答案截断

```python
import json, glob, collections

lens = collections.Counter()
for f in glob.glob('site/data/*.js'):
    s = open(f, encoding='utf-8').read()
    if ';window.UNIT_DATA[' not in s:
        continue
    j = s.index(';window.UNIT_DATA[')
    k = s.index('=', j)
    d = json.JSONDecoder().raw_decode(s[k+1:])[0]
    for q in d['questions']:
        lens[len(q[6] or '')] += 1

print(lens.most_common(5))   # 1200 高居榜首 → 有截断
```

### 手动复现悬空知识点

```python
import json, glob

for f in glob.glob('site/data/*.js'):
    s = open(f, encoding='utf-8').read()
    if ';window.UNIT_DATA[' not in s:
        continue
    j = s.index(';window.UNIT_DATA[')
    k = s.index('=', j)
    d = json.JSONDecoder().raw_decode(s[k+1:])[0]
    tids = {t['id'] for t in d['topics']}
    dangling = [q[0] for q in d['questions'] if q[1] not in tids]
    if dangling:
        print(d['unit'], len(dangling), '/', len(d['questions']))
```

**看什么**：若某个整数（如 1200）在长度分布里高居榜首，就是定长截断；
悬空题目数占比就是"练不到的题"。
